## 一、这个 skill 组解决什么问题

一个人（或一个小团队）用 AI 长期开发游戏时，真正的瓶颈不是"AI 写代码不够快"，而是：

- 每次开新对话都要重新解释一遍项目规则
- AI 会**顺手做完**它觉得该做的事，把模块边界慢慢写乱
- 多个 AI 并行时，各自理解的项目不一样，产出接不起来
- 文档过期后，下一个 AI 会**非常认真地**按错误信息继续开发

本 skill 组把应对方法固化成可复用的流程、模板与审计脚本。

## 三、安装

```bash
cd /workspace/云海猎团/skills/qq-rpg-ai-dev
bash install.sh                 # 软链安装（推荐：改一处两边生效，无漂移）
bash install.sh --copy          # 复制安装（项目目录可能被清理时用）
bash install.sh --uninstall     # 卸载
```

安装后在 agent 中即可通过 skill 名 `qq-rpg-ai-dev` 加载。

## 四、怎么用（最短路径）

1. 有个模糊想法 → 加载 skill，先读 `references/06-项目类型适配.md`
2. 走 `references/01-拆需求.md`，拿到问题清单和四层范围
3. 走 `references/02-拆模块.md`，产出模块边界卡
4. 用 `assets/任务单模板.md` 写任务单，**重点填"禁止修改"**
5. 派活：分析 → 实现 → 审查（审查不拿实现者的解释）
6. 收尾：回填 `DECISIONS.md`（用 `assets/裁决记录模板.md`），跑两个审计脚本

## 五、设计原则

- **只读审计**：`scripts/` 下脚本一律只报告不修改，退出码 `0` 通过 / `1` 有问题，便于接 CI。
- **单一数据源**：方法论细则只在 `references/` 里写一遍，`SKILL.md` 只做路由，避免多处维护漂移。
- **不做硬编码**：脚本的路径、文件清单、判定阈值一律走命令行参数或模块顶部常量。
- **模板即检查表**：每份模板的必填项都是一次真实事故换来的，不要随意删减字段。
