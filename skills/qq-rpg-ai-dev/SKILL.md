# QQ 群异步回合制 RPG·PvE · AI 协作开发方法论

> **Goal**: 让 AI 在这类项目里「每次都能接得上」，而不是每次重新解释一遍项目。
> 核心不是让 AI 多写代码，而是**先把边界说清楚**——模块边界、任务边界、文档边界。

## When to Use

触发本 skill 的信号：

- 要往这类项目里**新增**一个系统 / 模块 / 职业 / 武器 / 巨兽 / 战技
- 要**修改**已有数值、规则、公式，尤其涉及跨文件联动时
- 要**重构**或**增删功能**，需要评估「拆掉它会不会崩」
- 需求还很模糊（"我想加个 XXX 玩法"），需要先拆清楚
- 准备派**多个子 agent** 并行干活，先要定文件归属与共享事实
- 发现**文档与实现对不上**，需要判定谁是真相

## When NOT to Use

- 只是问一个已确定规则的具体数值（直接读常量表更快）
- 纯文案润色、错别字修正
- 一次性脚本、临时验证代码（不必走完整流程）

## 一、五阶段流程（主流程）

```
① 拆需求   →  ② 拆模块  →  ③ 写任务单  →  ④ 三角色接力  →  ⑤ 回填文档
  想法→问题     循环→模块     边界→验收     分析/实现/审查    事实→决策
```

**顺序不能跳。** 最常见的事故就是跳过 ①② 直接写代码——AI 会用"它脑子里默认的塔防/回合制"来补位，第一版看着能跑，后面每加一个功能都在还债。

|---|---|---|
| ① 拆需求 | 问题清单 + 四层范围表 | [references/01-拆需求.md](references/01-拆需求.md) |
| ② 拆模块 | 核心循环 → 模块边界卡 → 数据字段 | [references/02-拆模块.md](references/02-拆模块.md) |
| ③ 写任务单 | 允许新增/允许修改/禁止修改/规则/验收 | [references/03-任务单.md](references/03-任务单.md) |
| ④ 三角色接力 | 分析 → 实现 → 审查（审查须独立） | [references/04-多角色接力.md](references/04-多角色接力.md) |
| ⑤ 回填文档 | 项目事实 + 裁决记录 | [references/05-项目事实文档.md](references/05-项目事实文档.md) |

## 二、五条铁律（违反即返工）

1. **先说清楚，再写代码。** 需求没拆到"AI 不需要猜"的程度，不许开工。
2. **先拆数据，再拆逻辑。** 数值必须进常量表，一个数字只住一个地方。
3. **"不做什么"比"做什么"更重要。** 任务单里没有"禁止修改"清单，等于没写。
4. **文档最怕不是少，是旧。** 代码改了文档没改，下一个 AI 会**非常认真地**按错误信息继续开发。
5. **只加法。** 已发放的数值不下调；补偿弱组合靠加变体、加环境，不靠削弱别人。

## 三、角色定义（职责边界，不是头衔）

别写"你是一名资深 Unity 工程师"——那不产生区别。真正起作用的是**职责 / 不能做 / 输出**三件套：

| 角色 | 职责 | 不能做 | 输出 |
|---|---|---|---|
| **分析** | 把模糊想法拆成问题；指出缺失信息与风险 | 不写代码 | 问题清单、四层范围表 |
| **实现** | 按已确认任务单写代码/配置/文档 | 不改玩法规则；不自行新增系统；不做无关重构 | 改动说明、文件清单、自检结果 |
| **审查** | **独立对照原始规则**检查实现 | 不重写模块；不改需求；不加"更漂亮"的架构 | 必须改 / 建议改 / 需人工确认 三档 |

> 审查角色**不要拿到实现者的解释**，只给：原始任务单 + 改动后的代码 + 必要项目背景。
> 多角色协作的价值是**增加不同角度**，不是增加赞成票。

## 四、项目事实文档（所有角色共享同一份真相）

至少要有这五份（名字可改，职责不可少）：

| 文档 | 记什么 | 本项目对应 |
|---|---|---|
| `PROJECT.md` | 项目结构、技术约束、主要模块 | `README.md` |
| `GAME_RULES.md` | 已确认的玩法规则 | `00_世界观与术语规范.md` + `01_战斗核心系统.md` |
| `ARCHITECTURE.md` | 模块职责与公共接口 | `11_架构与模块化规范.md` + `12_全局常量表.md` |
| `TASK.md` | 当前任务目标、修改范围、验收 | 每次的任务单 |
| `DECISIONS.md` | **为什么**这么定；重评估条件 | `14_全局待裁决项与回填记录.md` |

模板见 [assets/项目事实文档集/](assets/项目事实文档集/)。

**代码与文档冲突时：先列冲突，不要自行判断谁对。** 这一条要写进审查角色的提示词。

## 五、可用脚本

```bash
# 审计模块边界声明完整性：每个模块是否写清了「负责 / 不负责 / 依赖」
python3 scripts/check_boundaries.py --root /workspace/云海猎团 --pattern "*_*.md"

# 检测文档新鲜度：代码比文档新 → 提示文档可能过期
python3 scripts/check_docs_freshness.py --root /workspace/云海猎团 \
    --docs README.md,00_世界观与术语规范.md,11_架构与模块化规范.md,12_全局常量表.md
```

两个脚本都只**报告问题、不改文件**（只读审计），退出码 `0` = 通过，`1` = 发现问题。
