# ⑥ 项目类型适配：QQ 群异步回合制 RPG·PvE

> **文件用途**：把①–⑤的通用方法论，落到「QQ 群异步回合制 RPG·PvE」这一具体项目类型上。**动手前先读这一份。**
> **创建时间**：2026-08-30
> **适用范围**：QQ 群 / 论坛帖 / Discord 频道等**异步、跨天、多人共斗**的回合制 PvE 项目

---

## 一、核心循环：这类项目和塔防根本不是一回事

**[02-拆模块.md](02-拆模块.md) 说"第一步是写核心循环"。** 这类项目的循环长这样：

```
接令（领任务 / 组队）
   ↓
战前配装（★ 所有决策在这里做完）
   ↓
开战 → 挂起（玩家离线）
   ↓
@推送 战报 → 玩家单次决策（≤30 秒）→ 再次挂起
   ↓
……循环 N 轮，可能跨天数……
   ↓
结算落库（素材 / 破坏部位 / 成就）
```

**与同步回合制的三个根本差异：**

| 维度 | 同步回合制 | **本项目类型** |
|---|---|---|
| 时间 | 连续，玩家在线等待 | **碎片、跨天**，玩家随时离线 |
| 阻塞 | 一人不操作，全场停 | **独立超时托管**，一人不操作不影响他人 |
| 交互 | 菜单、按钮、拖拽 | **文字指令**（`1`/`2`/`3`），战报即 UI |

> **最重要的认知**：在这类项目里，**"等待"不是循环的空档，而是一等公民**。
> 玩家离线的那几小时，系统必须有确定行为。这一点彻底改变了模块划分——
> 塔防里根本不存在"托管系统""推送调度""跨天单实例状态机"这些模块。

## 二、从循环里长出来的模块（对比塔防）

| 塔防的模块 | 本项目类型对应 | 差异点 |
|---|---|---|
| 波次系统 | 巨兽 / Boss 阶段机 | 同样的"按配置推进"，但驱动者是**意图预告 + 阶段转换** |
| 敌人系统 | 部位系统（可破坏 / 硬度 / 破坏槽） | 不是"打死一个怪"，是**逐步拆解** |
| 塔系统 | 职业 × 流派 × 武器 | ★ **武器与职业解耦**，14×14 = 196 种组合 |
| 子弹系统 | 九层伤害公式（结算管线） | 结算顺序是**规则本体**，改动风险最高 |
| BattleState | 战斗实例状态 | ★ **必须可持久化、可跨天续局** |
| BattleUI | **战报文案生成器** | ★ 唯一表现出口，且**受不刷屏约束** |
| — | **★ 托管 / 超时代打系统** | 塔防没有对应物 |
| — | **★ 推送调度系统** | 塔防没有对应物 |
| — | **★ 单实例生命周期** | 塔防没有对应物 |

**结论**：直接套用任何通用回合制架构，都会漏掉后三个模块——而它们恰恰是这类项目最难的部分。

## 三、五条类型专属铁律

### 铁律 1 · 战前配好，战内零菜单

玩家在战斗中被要求做的决策，必须是**单个、可一句话回答**的。

- 单次决策 ≤ **30 秒**
- 指令极简：`1` / `2` / `3`，不要要求记复杂语法
- 战报用 emoji + 短行，**不刷屏**

> **设计判据**：如果一个机制需要玩家在战斗中途打开配置面板调整，它就不该在这个项目类型里存在。

### 铁律 2 · 异步绝不阻塞全局

任何一个玩家掉线，**都不能让整局卡住**。

| 必须明确 | 典型取值思路 |
|---|---|
| 超时多久进入托管 | 按群活跃时段定，通常数小时 |
| 托管时代打策略 | 用玩家**战前配好的**默认策略，不新增决策 |
| 托管结果是否等同手动 | **必须等价**，否则离线玩家被惩罚 |
| 跨天如何续局 | 单实例持久化，回群发指令即续 |

### 铁律 3 · 无硬编码（工程侧最高优先级）

这类项目数值量极大（14 职业 × 14 武器 × 流派 × 战技 × 巨兽部位），硬编码必然失控。

**七条规则（N1–N7）**：

| # | 规则 | 含义 |
|---|---|---|
| N1 | 常量引用 | 所有数值写成 `$C.域.名`，禁止字面量散落 |
| N2 | 枚举化 | 状态、类型、层级一律枚举，禁止魔法字符串 |
| N3 | 表驱动 | 分支逻辑走配置表，不写 `if-else` 堆 |
| N4 | 零内容 ID | **内核层禁止出现任何具体内容 ID** |
| N5 | 条件 DSL | 解锁/触发条件写成可解析表达式 |
| N6 | 三层数值分离 | 基础值 / 加成 / 结算分属不同层 |
| N7 | 一处定义 | **一个数字只住一个地方** |

> **N7 是 N1 的验收标准**：如果同一个数值在两个文件里各写了一遍，就已经违规了。

### 铁律 4 · 只加法（数值侧最高优先级）

> ① 不下调已发放倍率；② 不削已发放符文 / 专械 / 超限阶位；③ 不删改任何战技变体、职业与武器。

发现某个组合偏弱 → **加**变体、加环境、加机制；**绝不能**通过削弱别人来对齐。

> **任务单里如果出现"下调某数值以对齐"，直接打回。**

### 铁律 5 · 软限制，不要硬体力

不要用体力/次数卡玩家。改成**发收益加成道具**：

```
每日发放 6 枚「丰饶符」→ 消耗 1/2/3 枚分别得到 ×2 / ×3 / ×5 收益
库存上限 24（可囤）
金币与经验不参与加成（防通胀）
```

**心理差异**：刷完当日份额后，玩家感觉是"继续刷收益一般"，而不是"怎么这么抠门"。

## 四、类型专属陷阱清单（AI 最容易踩的）

### 陷阱 1 · 「削减」类词汇的方向性 ⚠️ 高危

**这是本项目出过真实事故的地方。**

伤害公式里的 `H`（部位易伤系数）是**伤害乘区**——**H 越大越好打**。但中文说"部位硬度"，直觉上会写成 `H − 0.20` 表示"削减硬度"，实际效果是完全相反的（让目标更难打）。

曾因此产生三处独立 bug：

| 位置 | 原写法 | 实际效果 |
|---|---|---|
| 巨兽疲态期 | `核心件 H −0.40` | 本该是爆发期，却变得更难打 |
| 破甲突 | `max(H −0.30, MIN)` | 本该无视护甲，却让硬部位更硬 |
| 已破坏处 | `H 再 −0.20` | 本该奖励追打，却降低了伤害 |

**强制规范**：

```
✅ 正确：易伤 +0.20（H +0.20，更好打）
✅ 正确：硬度抗性 −0.20（等效 H +0.20）
❌ 禁止：裸的 "H −0.20"（方向不可判定）
```

> 涉及硬度 / 抗性 / 削减 / 无视 / 穿透的每一处，都必须**显式声明方向与等效关系**。

### 陷阱 2 · 频率类改动的二阶放大

"攻击段数 +1""充能速度 +20%"这类改动，**单点看改动很小，完整周期会放大**。

真实教训：某职业"速射压力 +15"与段数无关，单次看只是小buff，但叠加进 6 回合循环后整条曲线位移显著。

**规则**：涉及「加速 / 频率 / 段数 +N」→ **必须重跑完整周期 ΣM/回合**，不能只看单点。

### 陷阱 3 · 辅助职业没有伤害出口

辅助职业的资源全部换成团队增益后，**一旦团队增益被折算（防多人重复计数），它自己就崩了**。

真实教训：诗人团队增益占总当量 44.7%，个人裸 DPR 仅 0.546；统一套用 0.55 折算后直接跌到 0.789，跌破下限。

**规则**：设计辅助职业时，必须给它**把资源换成自己伤害的出口**。

### 陷阱 4 · 战报里塞太多东西

AI 天然倾向"信息完整"。但战报是群里的一屏消息，**塞满 = 刷屏 = 玩家关掉推送**。

**规则**：战报是**唯一表现出口**，但受不刷屏硬约束；逻辑层不关心文案，只产出结构化事件。

### 陷阱 5 · 把异步当同步写

AI 默认玩家"在线且立即响应"。写出来的逻辑往往**没有超时分支、没有离线等价性、没有跨天持久化**。

**规则**：每新增一个需要玩家输入的机制，必须同时回答：超时怎么办？托管时代打策略是什么？跨天怎么续？

## 五、常量表：这类项目的实际中枢

因为数值量极大，`12_全局常量表.md` 事实上是整个项目的**中枢**，不是附属文档。

**组织方式（A–L 十二域）**：

```
A 倍率与上限    B 战斗公式    C 时间/回合    D 伤害层
E 共生灵        F 异常        G 资源        H 成长
I 支援折算      J 指令与战报  K 经济        L 职业数值回写
```

**维护规则**：

1. **只能新增键，不能改名或删除**（改名 = 全库引用断裂）
2. 新职业卡的数值定稿后，**回写到 L 域**，让常量表成为唯一出处
3. 判定阈值、上限、折算率一律走常量，不要散在文档正文里

> 本项目常量表现有 200+ 处引用。**改一个键名的影响面，比你以为的大得多。**

## 六、建议的最短链路（MVP）

按 [02-拆模块.md](02-拆模块.md) 第八节"打通一条最短链路"：

```
1. 战斗实例能创建并持久化（跨天可续）
2. 玩家能用 1/2/3 发出一个指令，战报正确回显
3. 伤害公式九层能跑通一个完整例子
4. 巨兽有一个部位可被破坏
5. 超时能进入托管，结果与手动等价
6. 一局能正常结算并落库        ← 核心循环闭环
7. 再补：多职业 / 多武器 / 战技 / 推送 / 养成
```

**跑通 1–6 之前，不要同时开工 7。** 尤其是推送和养成——它们最容易把项目拖成"每个都写了一半"。

- [ ] 每个需要玩家输入的机制，都回答了"超时 / 托管策略 / 跨天续局"

- [ ] 内核层无具体内容 ID（N4）
- [ ] 涉及削减类词汇处，**方向已显式声明**（陷阱 1）

- [ ] 若为辅助职业，**个人伤害出口已确认**（陷阱 3）
