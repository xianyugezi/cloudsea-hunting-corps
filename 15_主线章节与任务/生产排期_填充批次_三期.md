## 零、全局纪律（每批次开工前必读）

1. **认领协议**：开工前重读本文件状态表 → 认领「编号最小的前置满足批次」→ 状态 ⬜→🔄 并填工人号与开始时间；Edit 失败＝被抢，重读后换下一批（重试一次）。**全局并发 ≤5**。🔒 批次（50）不可认领。
2. **只做本批次范围**；前置自检不满足 → 该批次回退 ⬜、原因写备注列，本轮结束。宁可空跑，不可越序生产。
3. **无硬编码**：共享数字一律 `$C.*` 引 `12_全局常量表.md`；新常量按批次任务书指示**自行落表**（三期先例：45 已收口、无终检代劳，沿批次 48 自行落表口径）或于设计者备注申报。
4. **收尾提交纪律**：完成判据全过后，先重读状态表改 ✅ 填日期，随后立即 `git add -A && git commit`；commit 失败等 5 秒重试至多 3 次，仍失败在备注尾注「⚠ 成果未提交待补录」（后续批次按第 5 条自愈补录）。
5. **脏树与死认领自愈**：开工见工作区脏 → 判定改动归属：属已 ✅ 批次成果 → 先补录提交（`fix(补录): 批次N成果`）再继续；属某 🔄 批次范围文件的半成品 → 视为在跑，不动；无法归属 → 本轮结束并报告。认领前见 🔄 批次且其范围文件无未提交改动、git log 无该批次提交 → 死认领，回退 ⬜（备注注「死认领回收+日期」）。
6. **同文件并发**：与其他执行器改同一文件不同行时，Edit 冲突等 60 秒重试；只改本批次对应行，不整段重写。
7. **🔒 整期推送纪律（本期新增，优先级最高）**：三期期间**任何批次只 `git commit`、禁止 `git push`**——五路并行下各自推送会在远端互相竞态阻塞；`git push` 仅由批次 51 收官统一执行并核验远端。
8. **完成判据**（grep／程序化断言）逐条真实执行，不许凭印象判过。未全过 → 状态回 ⬜、失败诊断写备注；同批次备注已有诊断且再次失败 → 标 🔴 待人工。
9. 全程中文；行文风格与既有文档一致（表格化、口径声明、自检表）。
10. **库容预算**：正文文件 ≤400 行或 ≤60KB，超限拆「总览索引＋一对象一文件」子文件夹（先例 13 卡／17 生态／18 图鉴）；批次执行日志写 `15_主线章节与任务/生产日志/`，状态表备注列只留 ≤40 字摘要。
11. **读取纪律**：开工只读「状态表＋本批次任务书＋其显式引用节」；大文件先 `grep -n` 定位行号再局部 Read（offset/limit），禁止无定位通读；合集 `云海猎团_设计稿合集.md` 为脚本生成物，执行器一律不读。
