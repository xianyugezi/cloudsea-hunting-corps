## 二、九段结构（顺序固定，缺段即不合格）

| # | 段名 | 内容要求 |
|---|---|---|
| 1 | **章节抬头** | 章号 / 中英文名 / 潮位 / 开放星段 / 舞台 / 首通星 / 首通 EHP / TTK / 上章 or 下章 or 教学章 or 终章 |
| 2 | **危机与叙事定位** | 一句话**危机**（本章要出什么事）+ 本章在十八章结构中的**职能**（铺陈 / 深入 / 收尾 / 拐点） |
| 3 | **剧情节点表** | 节点序 / 内容 / 战斗局数 / 教学序（无则 —）。节点数遵守总纲 M15.8 节奏表 |
| 4 | **章节 Boss** | Boss 名 / EHP / 机制核心 / 引用 `03` 对应小节。**不重新发明机制**，一律引用既有 |
| 5 | **主线任务清单** | **逐条命名**，条数**必须等于**本卡主线配额。字段见 §三 |
| 6 | **支线任务清单** | **逐条命名**，按系统来源分组，条数**必须等于**本卡支线配额。字段见 §三 |
| 7 | **本章解锁** | 系统 / 内容 / 装备线解锁清单（逐条） |
| 8 | **章末收尾** | 叙事收尾一句话 + ■**印记抉择**（若本章有；第 4 章起为替换制，上限 3） |
| 9 | **配额自检表** | 主线数 + 支线数 = 合计；支线各来源分项之和 = 支线数；与总纲配额表逐格对齐 |

## 三、任务清单字段（第 5 / 6 段）

| 字段 | 说明 |
|---|---|
| 序 | 本章内连续编号，主线 `主1…主N`，支线 `支1…支N` |
| 任务名 | **原创中文名**，4–10 字，带画面感；不得使用任何既有商业作品专有名词 |
| 目标 | 一句话说清打什么 / 做什么（含目标对象与数量） |
| 战斗 | `战 ×N` 或 `—`（非战斗节点） |
| 产出 | 主要素材 / 货币 / 解锁物 |
| 系统来源 | **必须**落在既有系统内：委托板 / 定向副本 / 蚀潮回廊 / 浮岛防卫战 / 蚀潮巨兽预警窗 / 周常轮替 / 剥取委托 / 潮根清剿。**禁止发明新玩法** |
| 频率 | 常驻 / 每周 / 每赛季 / 一次性 |

> **命名纪律**：任务名须能让玩家在 QQ 群里一眼看懂，避免抽象代号。例：`霜壳样本回收`、`融霜窗口推演`、`三枢座·风暴`。

## 五、四条硬纪律（改任何一张卡前先读）

1. **条数即契约**。主线 / 支线条数**必须精确等于**上表，**多一条少一条都不合格**。任务名可以调整，条数不可调整。
2. **支线不解锁难度，只给资源与叙事**。支线**不产出"推进资格"**——不打支线照样通关（与总纲 M15.4 开放规则③同源）。
3. **一律复用既有系统**。系统来源列只能填 §三 列出的 8 项之一，**不得发明新玩法**。
4. **不重复造轮子**。Boss 机制、蚀纹、异常一律**引用** `03` / `04` 既有条目，本卡只写"本章怎么用"，不重写机制定义。

## 六、常量引用（N1 无硬编码）

- 共享数字一律写 `$C.TIDE.*`（见 `../12_全局常量表.md` §T 域），**不得抄写数字**。
- 例：首通 EHP 写 `$C.TIDE.BASE_EHP[0] × $C.TIDE.STAR_COEF[1]`（一·微澜 ★1），不写 `16,800`。
- 仅本章专属数值（如某 Boss 的阶段阈值）可直接写数字。
- 常量表缺项：在文末「设计者备注」提出，以 `$C.域.新名（建议值 x）` 临时标注。
